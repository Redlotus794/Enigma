# 子域划分

> 本文档基于 enigma-demo 的业务能力划分子域，区分核心子域、支撑子域和通用子域。

## 子域类型定义

| 类型 | 说明 | 投入策略 |
|------|------|----------|
| **核心子域（Core Domain）** | 直接体现 demo 业务样例价值，是差异化的关键 | 第一阶段优先自研，重点表达业务规则 |
| **支撑子域（Supporting Subdomain）** | 支撑核心业务可运行、可验证、可学习 | 适度投入，保持实现简单 |
| **通用子域（Generic Subdomain）** | 通用技术能力，已有框架或 starter 可复用 | 优先复用 Spring Boot、Maven、Enigma starter |

## 子域划分

### 核心子域

| 子域名称 | 英文名 | 说明 | 包含的业务能力 |
|----------|--------|------|----------------|
| 角色管理 | Character Management | 管理特别任务支援科成员的基础状态、装备栏和可被其他子域引用的角色身份 | 创建角色、查看角色状态、调整角色状态、维护装备栏、拒绝非法角色操作 |
| 任务管理 | Mission Management | 管理支援任务的来源、状态、推进和完成 | 发布任务、受理任务、推进任务、完成任务、校验任务状态流转 |
| 导力器系统 | Orbment System | 按《碧之轨迹》最终形态设计导力器配置模型，管理核心回路、普通回路、槽位、属性值和导力魔法派生结果 | 安装核心回路、安装普通回路、替换回路、卸下回路、计算属性值、推导导力魔法 |

### 支撑子域

| 子域名称 | 英文名 | 说明 | 包含的业务能力 |
|----------|--------|------|----------------|
| 地图系统 | Map System | 支撑任务推进和商店访问，管理城市地图中的区域、地点、NPC、商店、任务入口和剧情触发点 | 维护城市区域、维护地点、查看地点元素、关联 NPC、商店、任务和剧情元素 |
| 背包系统 | Inventory System | 支撑角色准备和商店购买，管理角色持有物品及数量 | 查看背包、增加物品、扣减物品、校验物品数量 |
| 成就系统 | Achievement System | 支撑任务、探索、收集等达成记录；第一阶段仅划定边界，不强制实现 | 记录达成条件、查询成就状态、后续展示成就列表 |
| 示例展示 | Demo Presentation | 面向使用者展示核心业务样例的运行方式和观察入口 | README 指引、示例接口、示例数据、关键代码导航 |
| 业务规则验证 | Business Rule Verification | 通过测试证明业务规则稳定可见 | 合法路径测试、非法路径测试、模块级 Maven 测试 |

### 通用子域

| 子域名称 | 英文名 | 说明 | 包含的业务能力 | 推荐方案 |
|----------|--------|------|----------------|----------|
| Framework | Framework | 承载所有通用技术能力，不表达具体业务语义 | Spring Boot 启动、配置管理、Bean 装配、Maven 构建、BOM 依赖管理、测试插件、HTTP 接口、DTO、异常响应 | 复用 Spring Boot、Maven、`enigma-bom`、`enigma-parent`、`enigma-ddd-spring-boot-starter` 和项目 API 规范 |

## 子域与业务链路映射

| 核心链路 | 涉及子域 | 依赖关系 |
|----------|----------|----------|
| 城市任务推进链路 | 地图系统、任务管理、角色管理、导力器系统 | 地图系统支撑 NPC、商店、任务入口和剧情触发点；任务管理维护任务状态；角色管理提供执行者身份和状态；导力器系统提供角色准备能力 |
| 角色准备链路 | 角色管理、导力器系统 | 角色管理维护基础状态和装备栏；导力器系统维护导力器配置并输出属性值和导力魔法结果 |
| 商店购买链路 | 地图系统、背包系统 | 地图系统提供商店位置和出售物品；背包系统接收购买成功后的物品数量变更 |
| 地点探索链路 | 地图系统、任务管理、背包系统 | 查看城市地点时同步呈现 NPC、商店、可接任务和剧情触发点，商店购买结果进入背包 |

## 投入优先级

| 优先级 | 子域 | 类型 | 投入资源 |
|--------|------|------|----------|
| 1 | 任务管理 | 核心子域 | 第一阶段围绕任务受理、推进和完成形成主线 |
| 2 | 角色管理 | 核心子域 | 支撑执行者状态、装备栏和角色身份 |
| 3 | 导力器系统 | 核心子域 | 按《碧之轨迹》最终形态设计模型，第一阶段实现最小配置闭环 |
| 4 | 背包系统 | 支撑子域 | 本期实现，支撑商店购买和物品持有 |
| 5 | 地图系统 | 支撑子域 | 本期实现城市地图元素，支撑任务入口和商店 |
| 6 | 业务规则验证 | 支撑子域 | 跟随核心行为同步补充测试 |
| 7 | 示例展示 | 支撑子域 | 在核心闭环可运行后补充 README 和示例入口 |
| 8 | 成就系统 | 支撑子域 | 第一阶段只划定边界，后续实现 |
| 9 | Framework | 通用子域 | 复用 Enigma、Spring Boot、Maven 与项目基础规范，不拆分多个通用子域 |

## 子域边界决策

### 决策 1：角色管理、任务管理、导力器系统作为核心子域，地图系统、背包系统、成就系统作为支撑子域

**背景：** 第一阶段需要展示任务推进与角色准备，但地图、背包、成就主要支撑核心业务，不直接构成 demo 的差异化核心。

**决策：** 将角色管理、任务管理、导力器系统拆分为独立核心子域；将地图系统、背包系统、成就系统划为支撑子域。本期实现背包系统和商店能力，成就系统仅保留边界。

**原因：**

- 角色管理关注角色身份、状态和装备。
- 任务管理关注任务来源、状态和推进规则。
- 导力器系统具备独立规则复杂度，需按《碧之轨迹》最终形态设计。
- 地图系统关注城市空间结构和地图元素，用于支撑任务入口、NPC、商店和剧情触发点。
- 背包系统支撑商店购买和物品持有。
- 成就系统支撑达成记录，但第一阶段不作为实现重点。

**影响：** 后续战术设计应优先输出三个核心上下文，以及本期实现的地图、背包、商店支撑能力；成就系统可先形成边界说明。
