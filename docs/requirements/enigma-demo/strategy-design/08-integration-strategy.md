# 上下文间集成策略

> 本文档定义 enigma-demo 限界上下文之间的通信机制和技术选型。

## 集成原则

1. **核心上下文独立建模**：角色管理、任务管理、导力器系统、地图系统分别维护自己的模型。
2. **Framework 统一承载通用能力**：Spring Boot、Maven、DTO、异常响应、Enigma starter 等均归入 `Framework`，不再拆分通用子域。
3. **第一阶段优先同步调用**：demo 范围小，使用应用服务或 REST API 表达业务闭环。
4. **避免共享数据库**：上下文之间不直接共享存储结构。
5. **外部资料防腐**：接入外部游戏资料时通过 ACL 转换为本地模型。

## 集成策略详情

### 地图系统上下文 -> 任务管理上下文

**集成方式**：Published Language / API / 值对象引用。

**触发时机**：从城市地点、NPC 或剧情触发点创建或受理任务时。

**契约要点：**

| 能力 | 输入 | 输出 |
|------|------|------|
| 获取地点任务入口 | LocationId | MissionEntryView 列表 |
| 创建地图来源任务 | MissionSource | Mission |
| 校验任务来源 | MissionSource | 校验结果 |

### 任务管理上下文 -> 角色管理上下文

**集成方式**：API / 值对象引用。

**触发时机**：受理、推进或完成任务时需要确认执行角色存在。

**契约要点：**

| 能力 | 输入 | 输出 |
|------|------|------|
| 查询任务执行者 | CharacterId | CharacterSummary |
| 校验角色可用性 | CharacterId | 校验结果 |

### 角色管理上下文 -> 导力器系统上下文

**集成方式**：API / 查询视图。

**触发时机**：查看角色准备情况或配置角色导力器时。

**契约要点：**

| 能力 | 输入 | 输出 |
|------|------|------|
| 查询角色导力器 | CharacterId | OrbmentView |
| 配置导力器 | ConfigureOrbmentCommand | OrbmentView |
| 查询导力魔法结果 | CharacterId | ArtsView |

### Framework 上下文 -> 所有业务上下文

**集成方式**：Spring Boot 装配、Maven 构建、DTO、异常响应。

**触发时机**：应用启动、构建验证、接口调用和异常处理时。

**边界约束**：Framework 不包含角色、任务、导力器、地图的业务规则。

## 跨上下文领域事件清单

第一阶段不强制实现领域事件，以下事件作为后续候选。

| 事件名 | 事件类型 | 发布上下文 | 订阅上下文 | 事件内容概要 |
|--------|----------|------------|------------|--------------|
| CharacterCreated | Event | 角色管理上下文 | 任务管理上下文、示例展示上下文 | 角色创建成功后的标识、名称和初始状态 |
| CharacterStatusAdjusted | Event | 角色管理上下文 | 示例展示上下文、规则验证上下文 | 角色状态调整后的状态摘要 |
| OrbmentConfigured | Event | 导力器系统上下文 | 角色管理上下文、示例展示上下文 | 导力器配置、属性值和导力魔法摘要 |
| LocationViewed | Event | 地图系统上下文 | 示例展示上下文 | 地点及其 NPC、商店、任务、剧情元素被查看 |
| MissionAccepted | Event | 任务管理上下文 | 地图系统上下文、示例展示上下文 | 任务被角色受理 |
| MissionCompleted | Event | 任务管理上下文 | 地图系统上下文、示例展示上下文 | 任务完成 |

## 错误处理策略

| 场景 | 处理方式 | 重试策略 | 补偿机制 |
|------|----------|----------|----------|
| 角色输入非法 | 返回业务错误或抛出业务异常 | 不重试 | 保持原状态 |
| 导力器槽位不存在 | 返回业务错误或抛出业务异常 | 不重试 | 保持原导力器配置 |
| 地点不存在 | 返回未找到错误 | 不重试 | 无 |
| 任务来源不存在 | 返回业务错误或抛出业务异常 | 不重试 | 不创建或不推进任务 |
| 任务状态跳转非法 | 返回业务错误或抛出业务异常 | 不重试 | 保持原任务状态 |
| 后续事件重复投递 | 订阅方按事件 ID 幂等处理 | 可重试 | 忽略重复事件 |

## MVP 集成结论

MVP 使用应用服务作为核心集成方式，REST API 作为可选展示入口，测试直接调用领域行为或应用服务。`Framework` 承载所有通用技术能力，业务上下文只表达业务规则。
