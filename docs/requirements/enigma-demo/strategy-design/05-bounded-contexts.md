## 2. 背景与目标

### 2.1 业务背景

enigma-demo 需要展示业务项目如何围绕清晰业务场景组织代码。第一阶段业务范围聚焦特别任务支援科成员执行支援任务前的准备情况，包括角色状态、装备栏和导力器配置。

### 2.2 设计目标

- 明确角色任务准备相关模型的边界，避免演变成完整 RPG 系统。
- 区分核心业务规则、展示入口、测试验证和通用技术能力。
- 为后续战术设计提供统一语言、候选模型和集成关系输入。

### 2.3 非目标

- 不设计任务接取、任务执行、战斗结算、经验成长公式。
- 不设计完整物品库存、装备属性加成和回路属性加成。
- 不设计复杂数据库、中间件或外部系统集成。

## 4. 核心概念澄清

| 概念 | 角色任务准备上下文中的含义 | 示例展示上下文中的含义 | 规则验证上下文中的含义 | 处理方式 |

| 角色 | 具有名称、等级、经验、HP、MP、CP、基础战斗属性、装备栏、导力器配置的支援科成员 | 对外展示的角色状态视图 | 测试中构造和断言的业务对象 | 以角色任务准备上下文为权威模型，其他上下文使用 DTO 或测试夹具 |
| 状态 | 角色当前等级、经验、资源值和基础战斗属性 | 查询响应中的展示数据 | 测试断言的数据快照 | 不共享内部领域模型 |

| 回路 | 安装到导力器槽位的配置对象 | 展示导力器核心回路和普通回路 | 构造槽位占用、替换、卸下的测试数据 | 角色任务准备上下文内建模，暂不独立为完整回路系统 |
| 槽位 | 装备栏位或导力器槽位的位置约束 | 响应中的位置标识 | 测试非法槽位和合法槽位 | 在统一语言中区分装备栏位和导力器槽位 |

## 5. 上下文详情

### 5.1 角色任务准备上下文

| 项目 | 内容 |
| --- | --- |
| 中文名称 | 角色任务准备上下文 |
| 英文名称 | Character Readiness Context |
| 对应子域 | 角色任务准备 |
| 子域类型 | 核心 |
| 业务负责人 | 待确认 |
| 技术负责人 | Enigma demo 维护者 |

#### 核心职责

- 创建特别任务支援科成员并校验初始状态。
- 维护角色等级、经验、HP、MP、CP 和基础战斗属性。
- 维护角色装备栏中的武器、防具和两个饰品。
- 维护角色导力器中的核心回路和 7 个普通回路槽位。
- 拒绝违反业务规则的操作。

#### 边界说明

**包含：**

- 角色创建、查询、状态调整。
- 装备栏装备、替换、卸下。
- 导力器回路安装、替换、卸下。
- 角色不存在、装备栏位不存在、导力器槽位不存在等异常规则。

**不包含：**

- 任务、战斗、地图、剧情、经验成长公式、等级成长公式。
- 背包库存、装备来源、回路来源。
- 装备属性加成、回路属性加成和战斗数值计算。

#### 统一语言

| 术语 | 英文名 | 定义 | 备注 |
| --- | --- | --- | --- |
| 支援科成员 | Support Section Member | 被管理的角色对象 | 第一阶段可简称角色 |
| 角色状态 | Character Status | 等级、经验、HP、MP、CP 和基础战斗属性的组合 | 用于表达任务准备情况 |
| 装备栏 | Equipment Loadout | 武器、防具、饰品 1、饰品 2 四个装备栏位 | 每个栏位最多一件装备 |
| 导力器 | Orbment | 角色用于安装核心回路和普通回路的配置载体 | 包含 1 个核心槽位和 7 个普通槽位 |
| 回路槽位 | Quartz Slot | 导力器中可安装回路的位置 | 分核心槽位和普通槽位 |

#### 领域模型候选

| 类型 | 名称 | 说明 |
| --- | --- | --- |
| 聚合 | Character | 角色任务准备的聚合根，维护状态、装备栏、导力器配置 |
| 值对象 | CharacterStatus | 等级、经验、HP、MP、CP 和基础战斗属性 |
| 值对象 | BattleAttributes | STR、DEF、AGL、ATS、ADF、SPD、DEX、MOV、RNG |
| 值对象 | EquipmentLoadout | 武器、防具、饰品 1、饰品 2 的栏位配置 |
| 值对象 | Orbment | 1 个核心回路槽位和 7 个普通回路槽位的配置 |
| 枚举 | EquipmentSlot | WEAPON、ARMOR、ACCESSORY_1、ACCESSORY_2 |
| 枚举 | OrbmentSlot | CORE、NORMAL_1 至 NORMAL_7 |
| 仓储 | CharacterRepository | 保存和查询角色聚合 |

#### 业务规则

- 角色名称不能为空。
- 等级不能小于 1。
- 经验、HP、MP、CP 和基础战斗属性不能小于 0。
- 同一个装备栏位同时只能装备一件装备。
- 空装备栏位可以装备物品，已占用栏位可以替换或卸下。
- 导力器包含 1 个核心回路槽位和 7 个普通回路槽位。
- 每个导力器槽位同时只能安装一个回路。
- 空导力器槽位可以安装回路，已占用槽位可以替换或卸下。
- 对不存在的角色、装备栏位、导力器槽位执行操作必须被拒绝。

#### 状态与生命周期

| 对象 | 状态 | 可触发动作 | 下一个状态 | 规则说明 |
| --- | --- | --- | --- | --- |
| 角色 | 已创建 | 调整状态 | 已更新 | 新状态必须满足等级和数值约束 |
| 装备栏位 | 空栏位 | 装备 | 已装备 | 栏位必须存在 |
| 装备栏位 | 已装备 | 替换 | 已装备 | 替换后仍保持单栏位单装备 |
| 装备栏位 | 已装备 | 卸下 | 空栏位 | 栏位必须存在 |
| 导力器槽位 | 空槽位 | 安装回路 | 已安装 | 槽位必须存在 |
| 导力器槽位 | 已安装 | 替换回路 | 已安装 | 替换后仍保持单槽位单回路 |
| 导力器槽位 | 已安装 | 卸下回路 | 空槽位 | 槽位必须存在 |

## 7. 集成策略

### 7.1 同步集成

- 场景：示例展示上下文调用角色任务准备上下文完成创建、查询、调整、装备、导力器配置。
- 接口契约：使用应用服务或 REST API 传递命令 DTO 和查询 DTO。
- 超时与重试：第一阶段为本地进程内调用，不设计重试。
- 错误处理：业务异常转换为清晰错误响应或测试断言。

### 7.2 异步集成

第一阶段不引入消息队列。若后续需要展示领域事件，可从角色已创建、角色状态已调整、装备已更换、导力器已配置等事件开始。

### 7.3 防腐层

第一阶段没有外部系统。若后续接入完整游戏数据、第三方装备库或回路库，应通过防腐层转换为本地装备与回路模型。

## 8. 边界决策记录

### 决策 1：装备和导力器暂不拆分为独立核心上下文

**背景：** PRD 第一阶段只要求表达角色执行任务前的准备情况。

**备选方案：**

- 方案 A：设置角色、装备、导力器三个核心上下文。
- 方案 B：设置一个角色任务准备核心上下文，装备和导力器作为角色准备的一部分。

**决策：** 采用方案 B。

**原因：** 第一阶段没有库存、装备来源、回路来源、属性加成等独立业务生命周期，拆分上下文会增加不必要复杂度。

**影响：** 后续若引入库存或装备成长，可再把装备配置或回路配置拆出独立上下文。
