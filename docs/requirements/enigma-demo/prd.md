# enigma-demo PRD

## 1. 背景

Enigma 需要一个标准示例工程，用于展示业务项目如何围绕清晰的业务场景组织代码，并通过可运行样例帮助使用者理解框架的基本用法。

当前 `enigma-demo` 将从零开始重新设计，不沿用既有示例代码。

## 2. 产品定位

`enigma-demo` 是 Enigma 框架的标准示例工程，用于演示业务项目如何基于 `enigma-ddd-spring-boot-starter` 构建一个小而完整的业务样例。它不是玩具 CRUD，而是一个围绕明确业务规则组织的可运行示例。

## 3. 目标用户

- Enigma 框架使用者：通过 demo 学习如何创建标准业务项目。
- 后端开发者：参考 demo 理解业务规则如何在代码中表达、验证和演进。
- 框架维护者：通过 demo 验证 starter 的核心能力是否可用、易用、可解释。

## 4. 产品目标

- 提供一个从零开始的标准业务样例。
- 展示清晰的业务对象、业务动作和业务规则。
- 展示一个小而完整的业务样例，而不是面向数据库表的贫血 CRUD。
- 展示 `enigma-ddd-spring-boot-starter` 的基础使用方式。

## 5. 非目标

- 不追求完整业务系统能力。
- 不引入复杂数据库、中间件或外部系统依赖。
- 不把 demo 做成通用脚手架生成器。
- 不覆盖 Enigma 所有 starter 能力，只覆盖最基础、最常用、最能说明业务样例实现方式的能力。

## 6. 示例业务方向

`enigma-demo` 以日式 RPG 游戏《零之轨迹》《碧之轨迹》的克洛斯贝尔自治州为背景，选取“特别任务支援科成员养成与任务准备”作为示例业务方向。

特别任务支援科成员在执行支援任务前，需要确认自身状态、调整装备，并配置导力器回路，以便应对调查、探索和战斗。

本示例不复刻完整游戏系统，只抽取角色状态、装备栏和导力器配置作为第一阶段业务样例。

## 7. 核心业务场景

第一阶段实现角色状态管理。特别任务支援科成员需要维护自己的基础状态、装备栏和导力器配置，用于表达角色在执行支援任务前的准备情况。

基础业务范围：

- 角色状态：记录角色名称、等级、经验、HP、MP、CP 和基础战斗属性。
- 装备栏：管理角色当前装备的武器、防具和两个饰品。
- 导力器：管理角色导力器中的核心回路和普通回路配置。

基础业务流程：

- 创建角色：登记支援科成员的基础信息和初始状态。
- 查看角色状态：查看角色当前等级、经验、HP、MP、CP、基础战斗属性、装备和导力器配置。
- 调整角色状态：更新角色等级、经验、HP、MP、CP 或基础战斗属性。
- 更换装备：为角色装备或卸下武器、防具、饰品。
- 配置导力器：为角色安装或卸下回路。

基础业务规则：

- 角色名称不能为空。
- 等级不能小于 1。
- 经验、HP、MP、CP 和基础战斗属性不能小于 0。
- 同一个装备栏位同时只能装备一件装备。
- 空装备栏位可以装备物品，已占用栏位需要先卸下或替换。
- 导力器包含 1 个核心回路槽位和 7 个普通回路槽位，不能超过可用槽位数量。
- 已安装回路的槽位不能重复安装，必须先卸下或替换。

## 8. 业务表达要求

- 示例必须围绕角色状态管理展开，不偏离第一阶段业务范围。
- 业务动作必须使用清晰的业务语言命名。
- 角色状态、装备栏和导力器配置必须有明确规则。
- 非法业务操作必须被明确拒绝。
- 示例代码应能让使用者直接看出业务规则在哪里被校验。

## 9. 示例展示范围

MVP 必须展示：

- 角色创建。
- 角色状态查看。
- 角色状态调整。
- 装备栏更换。
- 导力器回路配置。
- 业务规则测试。

可选展示：

- 测试工具的推荐用法。

## 10. 功能需求

### 10.1 创建角色

系统应支持创建特别任务支援科成员，并记录角色的初始状态。

创建角色时需要填写：

- 角色名称。
- 初始等级。
- 初始经验。
- 初始 HP。
- 初始 MP。
- 初始 CP。
- 初始攻击力 STR。
- 初始防御力 DEF。
- 初始回避率 AGL。
- 初始法术攻击力 ATS。
- 初始法术防御力 ADF。
- 初始速度 SPD。
- 初始命中率 DEX。
- 初始移动力 MOV。
- 初始攻击范围 RNG。

创建角色时应校验：

- 角色名称不能为空。
- 初始等级不能小于 1。
- 初始经验不能小于 0。
- 初始 HP 不能小于 0。
- 初始 MP 不能小于 0。
- 初始 CP 不能小于 0。
- 初始基础战斗属性不能小于 0。

### 10.2 查看角色状态

系统应支持查看角色当前状态，用于确认角色执行支援任务前的准备情况。

角色状态信息应包括：

- 角色名称。
- 当前等级。
- 当前经验。
- 当前 HP。
- 当前 MP。
- 当前 CP。
- 当前攻击力 STR。
- 当前防御力 DEF。
- 当前回避率 AGL。
- 当前法术攻击力 ATS。
- 当前法术防御力 ADF。
- 当前速度 SPD。
- 当前命中率 DEX。
- 当前移动力 MOV。
- 当前攻击范围 RNG。
- 当前装备栏。
- 当前导力器配置。

### 10.3 调整角色状态

系统应支持调整角色的等级、经验、HP、MP、CP 和基础战斗属性。

调整角色状态时应校验：

- 等级不能小于 1。
- 经验不能小于 0。
- HP 不能小于 0。
- MP 不能小于 0。
- CP 不能小于 0。
- 基础战斗属性不能小于 0。

### 10.4 更换装备

系统应支持为角色装备或卸下武器、防具和饰品。

装备栏应至少包含：

- 武器栏位。
- 防具栏位。
- 饰品栏位 1。
- 饰品栏位 2。

更换装备时应满足：

- 同一个装备栏位同时只能装备一件装备。
- 空装备栏位可以直接装备物品。
- 已占用栏位可以通过替换操作更换装备。
- 已占用栏位可以通过卸下操作变为空栏位。

### 10.5 配置导力器

系统应支持为角色导力器安装、替换或卸下核心回路和普通回路。

配置导力器时应满足：

- 导力器拥有 1 个核心回路槽位。
- 导力器拥有 7 个普通回路槽位。
- 每个槽位同时只能安装一个回路。
- 空槽位可以直接安装回路。
- 已安装回路的槽位可以通过替换操作更换回路。
- 已安装回路的槽位可以通过卸下操作变为空槽位。

### 10.6 异常操作处理

系统应拒绝明显不合法的业务操作。

需要拒绝的操作包括：

- 使用空名称创建角色。
- 使用小于 1 的等级创建或调整角色。
- 使用负数经验创建或调整角色。
- 使用负数 HP 创建或调整角色。
- 使用负数 MP 创建或调整角色。
- 使用负数 CP 创建或调整角色。
- 使用负数基础战斗属性创建或调整角色。
- 对不存在的角色进行查询或操作。
- 对不存在的装备栏位进行装备或卸下操作。
- 对不存在的导力器槽位进行安装、替换或卸下操作。

## 11. 测试与验收标准

- 角色创建规则必须有测试覆盖。
- 角色状态调整规则必须有测试覆盖。
- 装备栏更换规则必须有测试覆盖。
- 导力器配置规则必须有测试覆盖。
- 示例代码必须能通过模块级 Maven 测试。
- README 必须能指导使用者运行 demo 并理解示例业务。
