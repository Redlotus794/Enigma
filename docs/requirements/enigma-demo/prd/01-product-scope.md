# PRD 01 - 产品范围

## 1. 示例业务方向

`enigma-demo` 以日式 RPG 游戏《零之轨迹》《碧之轨迹》的克洛斯贝尔自治州为背景，选取“特别任务支援科推进任务与角色准备”作为示例业务方向。

特别任务支援科成员在城市地图中与 NPC、商店、任务和剧情元素交互，推进支援任务；执行任务前需要确认自身状态、调整装备，并配置导力器系统，以便应对调查、探索和战斗。

本示例不复刻完整游戏系统，第一阶段抽取角色管理、任务管理、导力器系统作为核心业务样例，并以地图系统、背包系统和商店能力支撑任务推进与角色准备。导力器系统按《碧之轨迹》最终形态作为目标模型设计，但第一阶段只实现能支撑 demo 的最小业务闭环。

## 2. 基础业务范围

- 角色管理：记录角色名称、等级、经验、HP、MP、CP、基础战斗属性和装备栏。
- 任务管理：记录支援任务的发布、受理、推进、完成等状态。
- 导力器系统：管理角色导力器的核心回路、普通回路、槽位、属性值和导力魔法配置。
- 地图系统：支撑城市地图中的区域、地点、NPC、商店、任务入口和剧情触发点。
- 背包系统：支撑角色持有道具、装备、回路和消耗品。
- 商店能力：支撑从城市地图中的商店购买物品。
- 成就系统：作为支撑子域预留，用于记录任务、探索、收集等达成结果；第一阶段不强制实现。

## 3. 业务表达要求

- 示例必须围绕角色管理、任务管理、导力器系统，以及支撑这些核心业务的地图、背包和商店能力展开，不偏离第一阶段业务范围。
- 业务动作必须使用清晰的业务语言命名。
- 角色状态、装备栏、导力器配置、任务状态、地图元素、背包物品和商店购买必须有明确规则。
- 非法业务操作必须被明确拒绝。
- 示例代码应能让使用者直接看出业务规则在哪里被校验。
